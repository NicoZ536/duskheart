# RENDER – Verträge für Asset-Pipeline und Renderer

Ergänzt MASTERPROMPT §4–§6 und docs/ARCHITEKTUR.md. Änderungen nur per ADR.

## 1. Sprite-Quellformat (`assets-src/sprites/**/*.ts`)
```ts
import { sprite } from '../../lib/sprite';
export default sprite({
  id: 'fackel_wand',            // snake_case, global eindeutig
  group: 'licht',               // Kontaktbogen-Gruppe
  size: [16, 16],               // Zellgröße je Frame
  anchor: [8, 15],              // Fußpunkt (y-Sortierung, Platzierung)
  hoehe: 'zylinder',            // flach | zylinder | kugel | block | custom (Normal-/Höhengenerator)
  legende: { '.': null, o: 'holz.2', O: 'holz.4', f: 'feuer.3*', F: 'feuer.5*' }, // * = emissiv
  frames: [`...`, `...`],       // Index-Raster, Zeilen per Template-String, Einrückung wird entfernt
  clips: { idle: { frames: [0, 1, 2, 3], fps: 10, loop: true } },
  hitbox: [4, 10, 8, 6],        // x, y, w, h relativ zur Zelle (optional)
  sockets: { hand: [[10, 12], …] },   // je Frame (optional)
  occluder: { kind: 'ellipse', x: 8, y: 14, rx: 3, ry: 2 },  // none | rect | ellipse | sprite (optional)
  schatten: 'silhouette',       // Sonnenschatten aus Silhouette (Standard) | none
  material: { metall: 'M', nass: 'W' }, // optional: Zeichen mit Materialflags
});
```
- Ein Zeichen = ein Palettenindex (`rampe.stufe`, **Stufen ab 0**: `feuer.0` ist die dunkelste Stufe; das Literal-Beispiel `feuer.6` in MASTERPROMPT §5 zählt ab 1 und entspricht `feuer.5`), `*` markiert emissive Pixel; exakte Palettenfarben als `#rrggbb` sind in der Legende ebenfalls erlaubt. ≤ 12 Farben je Sprite (Ausnahmen per `ausnahmeFarben: 'Begründung'`).
- Ergänzungen (ADR-0014): `group` ist optional (Standard: Ordnername); ein einzelner Sockelpunkt gilt für alle Frames; Clips können `events` tragen; optional `spiegelbar` (Spiegeln erlaubt), `einzelpixel` (Begründung für gewollte Einzelpixel), `hoehenRaster` (manuelle Höhe, Pflicht bei `hoehe: 'custom'`); ein Materialflag `true` gilt für alle deckenden Pixel. Dateien, die mit `_` beginnen, sind Hilfsmodule und werden nicht als Sprite gelesen.
- Dateien exportieren ein Sprite, ein Array oder das Ergebnis eines Generators (`generate(seed, …)` → Sprites). Generatoren sind deterministisch (eigener `Rng` aus `src/engine/rng.ts`).
- Palettenzeilen-Varianten (Jahreszeiten, Biom-Tönung, Elite, Verderbnis, Materialstufen, Charakteranpassung) in `assets-src/paletteRows.ts`: jede Zeile bildet jeden der 64 Indizes auf einen Palettenindex ab.

## 2. Generierte Artefakte (`npm run assets`, gitignored)
- `public/generated/atlas-albedo.png` – RGBA8: **R** = Palettenindex (1…64, 0 = transparent), **G** = Emissiv (0/255), **B** = Materialflags (Bit 0 Metall, Bit 1 nass/glänzend, Bit 2 Eis, Bit 3 Wind-Biegung, Bit 4 Blätterdach/Dach, Bit 5 Occluder – jedes Pixel eines Sprites mit Occluder-Standfläche außer Dachpixeln, M5-01, ADR-0051), **A** = Deckung (0/255).
- `public/generated/atlas-normal.png` – RGBA8: **RG** = Normale XY (0.5 + 0.5·n, **+y = oben** auf dem Bildschirm, wie der G-Buffer, ADR-0011), **B** = Höhe (0…255 ≙ 0…32 px über Boden), **A** = Deckung.
- `src/generated/atlas.ts` – Manifest: Atlasgröße, je Sprite: Frames (x, y, w, h), Anker, Hitbox, Sockel je Frame, Clips, Occluder, Höhen-Hinweis (`hoehe`), emissiv (`emissiv`), spiegelbar (`spiegelbar`), Gruppe, dazu `schatten` (`basisY`, `bounds`), `bounds`, `material`, `farben`; Palettenzeilen-Tabelle (`{ id, beschreibung, map }`, `map[i]` = Index für Index `i + 1`); Quell-Hash. Der Renderer liest es über den Adapter `src/render/assets/generated.ts` (zod-geprüft) in sein `AtlasManifest`.
- `src/generated/palette.ts` – Master-Palette (64 + 8 UI), Rampen, Raritätsfarben als Palettenreferenzen (`RARITY_REFS`).
- `tools/out/sheets/<gruppe>.png` – Kontaktbögen (Albedo auf hellem und dunklem Grund, Normalen, Emissiv, Animationsraster, 4× vergrößert); dazu `palette.png`, `normals.png`, `vorschau_gruenhain.png` (Kachelfelder + Szene), `biome.png` (Biom-Tönung), `ui-kit.png`.

## 3. Renderer (`src/render`)
- `gl/` Kontext, Programme (`#include`), Ressourcen (Textur, Framebuffer inkl. MRT, Buffer, VAO), Float-RT-Erkennung mit RGBA8-Fallback, Kontextverlust → alles neu aufbauen.
- `assets/atlas.ts` lädt Atlanten + Manifest; `palette/lut.ts` baut die Paletten-LUT (64 × Zeilen, RGBA8).
- `camera.ts`: Welt in Pixeln; Kamera ganzzahlig, Nachkommaanteil als Subpixel-Offset im Präsentationspass; Szene mit 1 px Rand.
- `batch/spriteBatcher.ts`: instanzierte Quads. Instanzattribute: Position (Welt-px, Anker), Atlas-Rect, Palettenzeile, Tiefe (y-Sortierung), Höhe-Basis, Flags (Spiegeln, Outline, Weißblitz, Emissiv-Verstärkung, Dither-Ausblendung), Wind-Parameter, Tönung RGBA8, Rotation. Keine Allokation pro Frame (vorab reservierte Typed Arrays). Upload (M5-51): nur die Spannen geänderter Datensätze gegenüber dem Pufferinhalt des letzten Frames (höchstens 8 `bufferSubData`, ein Standbild lädt nichts), kein Verwaisen des Puffers im Frame-Pfad; je Ebene ein Vertex-Array, neu ausgerichtet nur, wenn der erste Datensatz der Ebene wandert.
- `tilemap/chunkMesh.ts`: statische Boden-Meshes je Chunk, Neuaufbau nur bei Änderung.
- Pässe (`passes/`, Plätze `PASS_ORDER`, ADR-0065): Interaktionstextur der Oberfläche (90) → G-Buffer (100; MRT: G0 Albedo · G1 Normale XY + Höhe + Materialflags · G2 Emissiv + Glanz/Nässe) → Occluder/SDF (200) → Sonnen-/Mondschatten (300) → Licht (400, RGBA16F) → Komposition (500) → Pfützen (520) → Verderbnis (550) → Wasser (600) → Hitzeflimmern, Partikel, Blitz (650) → Atmosphäre (700) → Verzerrung (760) → Bloom (780) → Post (800: Tonemapping, Grading-LUT, Zustände, Vignette, Korn; ersetzt `resolve` 900) → Umriss (950) → Debug-Overlays (970) → CRT-Schalter (975) → Welt-UI (980) → Präsentation (scharfes Hochskalieren + Subpixel, optional CRT als Schlussschritt).
- `RenderScene` (pro Frame von der Präsentationsschicht befüllt): Kamera, Tiles/Chunks, Sprite-Instanzen, Lichter (`LightInstance`: Position, Höhe, Boden (Ebene × 16 px, sonst aus der Occluder-Maske), Radius, Farbe, Intensität, Flackern, Kegel), Umgebungslicht, Zeit, Wetter-/Grading-Parameter. Die Lichtliste stammt aus derselben Quelle wie die Gameplay-Lichtkarte (§12.1).
- Weltnahe UI (ADR-0014): `RenderScene.worldUi` (Namen, Leisten, Schadenszahlen, Interaktionsmarker in Weltpixeln) zeichnet der Pass `welt-ui` (`passes/worldUiPass.ts`, `PASS_ORDER.worldUi`, nach Outline) mit dem Glyphenatlas der Pixelschrift (`text/`) ins LDR-Ziel – unbeleuchtet, auf ganzen internen Pixeln, ein Draw-Call. Ein Interaktionsmarker trägt eine Sperrfläche (die Figur des Spielers, `WorldUiList.marker(…, avoid)`): würde er sie verdecken, hebt der Pass ihn über ihren Kopf (`markerBottomClearOf`, ADR-0034); zeigt das HUD den Hinweis, ist der Marker nur die Tastenkappe. Über einem Nutzziel (Lagerfeuer, Fackel, Station, Kiste, Tür, Grab) steht der Marker auf der Oberkante der deckenden Pixel seiner umrandeten Sprites samt Flamme plus Abstand, mittig über ihren Ankern: `GatheringView.liftUseMarker` liest nach Gräbern, Bauraster, Stationen und Lichtern die umrandeten Datensätze des Frames aus der Sprite-Liste zurück (`outlinedSince`; Oberkante je Clip aus der Deckung des Albedos, beim ersten Bedarf gelesen – `FrameTops`, ohne lesbares Bild `AtlasSprite.bounds` –, damit der Marker nicht mit den Flammen wippt, M5-65).
- Standardszene der Seite ist `spiel` (Spielansicht, ADR-0026): die Welt der Sitzung unter der Kamera der gesteuerten Figur, hinter dem Titel der Startstrand; die M1-Lichtung `gruenhain` und die übrigen Szenen über `__dh.call('renderScene', id)` bzw. Szenarien.
- **Welt-Darstellung** (`world/`, ADR-0025): `tables.ts` (Laufzeit-Ids → Tileset-Frames, Biomzeilen, Klippengruppen, Objekt-Sprites), `window.ts` (Chunk + Nachbarrand), `terrainMesh.ts`/`terrainPass.ts` (statische Instanz-Meshes je Chunk, ein Draw-Call je sichtbarem Chunk, Neubau nur bei geänderter Inhaltssignatur des Chunks oder eines Nachbarn, `shaders/world/terrain.*`), `shading.ts` (Schatten als Palettenstufen aus dem Höhenfeld), `objects.ts` (y-sortierte Objekte, Jahreszeit-/Abgeerntet-Frames, Blätterdach-Ausblendung), `signature.ts`, `showcase.ts`, `worldHost.ts` (Welt im Welt-Worker + Streaming über den `ChunkManager`; fällt der Worker vor der Welt aus, erzeugt derselbe Code sie im Hauptthread, sonst meldet `onError` den Grund, ADR-0027; fällt er während der Sitzung aus – abgelehnter Auftrag oder 5 s ohne Antwort –, lädt `WorkerFailover` die Chunks mit einer Warnung im Hauptthread weiter, im Frame-Budget, ADR-0033; Modus `adopt`: die Welt der Sitzung geht an die Simulation, gestreamt wird deren Chunk-Store), `groundDecor.ts` (Dünengras-Horste der Salzküste als flache Streuobjekte über Kachelgrenzen, M3-40, ADR-0033), Meeresgrund ohne 16-px-Raster (M5-67: schlichter Tiefgrund als Füllung, Senken mit Lichtwellen als blaues Rauschen `SEABED_HOLLOWS`, Steine und Seegras `SEABED_MOTIFS`; nie zwei in einer Reihe oder Spalte zwei Kacheln nah), `worldScene.ts` (Debug-Szenen `gruenhain-tag`, `frostkamm-tag`, `glutsand-tag`, `ebene-1-roh` mit eigener Welt), `gameScene.ts` (Spielansicht `spiel`: Kamera folgt der Figur samt Ebene, sonst freie Kamera ab dem Titelbild; Licht aus Kalender und Wetter; Handlicht der Figur bei Dunkelheit), `debugCamera.ts` (Pfeiltasten, nur im Debug-Modus).
- **Debug-Overlays** (M2-29, ADR-0026): `RenderScene.debugOverlay` (gepoolte Rechtecke und Beschriftungen in Weltpixeln), gezeichnet vom Pass `debug-overlay` (`PASS_ORDER.debugOverlay`, nach Umriss, vor der Welt-UI, unbeleuchtet, ein Draw-Call, Glyphenatlas der Pixelschrift). Erzeuger `world/overlays.ts`: `chunks` (Zustand aktiv/eingefroren/lädt/fehlt, Koordinaten), `kollision` (Kategorien des `CollisionGrid`, Rampen/Treppen), `temperatur` (5-°C-Bänder, Werte alle acht Kacheln); Schalter `__dh.call('worldOverlay', name, an)` bzw. Konsole `overlay`. Beschriftungen lesbar (M6-Gate, ADR-0170; `queueDebugOverlay`): erst alle Rechtecke, dann jede Beschriftung auf einer dunklen Platte (`DEBUG_LABEL`), ganz ins Bild gerückt; überdeckt sie eine frühere, rückt sie darunter (am unteren Rand darüber, `DebugLabelPlacer`).
- **Spielfigur und Spielgeschehen** (`game/`, ADR-0033): `playerFigure.ts` (Körper-Clips, Gegenstände an den Hand-Sockeln, Kleidung, Zustands-Look), `figureFx.ts` (Zittern, Atem, Flammen), `objects.ts` (Fokus-Umriss, Marker, Fortschrittsring, Drops mit Glitzern im Dunkeln), `lights.ts` (die Lichtquellenliste der Simulation als `LightInstance`, Lagerfeuer- und Fackel-Sprites), `graves.ts`.
- **Bauen (M4, `game/building.ts`, `ghost.ts`, `overlays.ts`, `roofs.ts`):** Bauteile als Sprite-Instanzen (`bau_<id>` für Struktur, Boden, Dach; `obj_<id>` für Möbel, Kisten, Herdfeuer; Tor `…_seite`, Falltür `…_klappe`; Wände verbinden sich über `connectMask`, Wandobjekte hängen an der Front der Wand nördlich ihrer Kachel, Fenster beleuchteter Räume glühen nachts). Geister-Vorschau, Bau-Overlays (Räume/Typen, Raumtemperatur in lesbaren Stufen, Licht, Behaglichkeit, Stützen) und Rasterfelder laufen über den bestehenden Pass `debug-overlay`, die Begründung über dem Geist über die weltnahe UI; Dächer eines Innenraums blenden beim Betreten ganz aus, sonst öffnen sie sich wie Kronen im Kreis-Dither um den Spieler (dieselbe Kennung wie das Kronen-Ausblenden). Keine neuen Pässe oder Shader.
- **GPU-Partikel, Wetter, Feuer (M5-11, M5-12, M5-21, ADR-0056, ADR-0057; `particles/`, `passes/particlePass.ts`):** Arten, Quellen, Wetterpartikel und Blitz als Daten in `src/content/particles/` (Registry-Sammlungen `particleKinds`, `particleEmitters`). Simulation per Transform Feedback in zwei Puffern (36 864 Datensätze à 3 × vec4: Wetterpool 8 192 vorn – geschritten und gezeichnet nur so weit, wie das Wetter Teilchen braucht –, Ring 28 672 dahinter), Geburten deterministisch auf der CPU (`spawn.ts`: Ordinalzahl je Quelle, Zufall aus Hashes, Alter ≤ 0 innerhalb des Schritts), Zeichnen als instanzierte Quads auf ganzen Pixeln ins HDR-Ziel (vorab multipliziertes Alpha in acht Stufen), beleuchtet mit Umgebungslicht + Punktlicht-Puffer am Fußpunkt (spektral wie die Komposition; das Punktlicht weich über dem Umgebungslicht, `pointOverDaylight(uAmbient, uDayLevel)` aus `composite_daylight.glsl` – mittags gewinnt eine Flocke am Herd nichts, nachts fast alles, in Höhlen alles; ebenso das Partikellicht auf Ultra, M5-41). Neustart mit 5 s Vorlauf ohne Zustand, nach Kontextverlust, bei Zeitsprung und bei eingefrorener Zeit mit geänderten Quellen (Screenshots zeigen den eingeschwungenen Zustand genau ihrer Quellen); der Vorlauf läuft in Schritten von 0,5 s, je ein Feedback-Durchgang mit Unterschritten ≤ 1/30 s (zehn Draw-Calls statt 150). Pässe am Platz `particles` 650: `heat-shimmer` (Hitzesäulen aus `scene.particles.distortion`; läuft der Verzerrungspass der Post-Kette, gehen sie als Hitzeflächen in `scene.post.distortion`), `particles`, `lightning` (Vollbildblitz: jede Fläche spiegelt das kalte Licht, ein Schleier davon liegt über dem ganzen Bild; mit Blitzreduktion ein weicher Puls ≤ ¼). Befüllt von `world/particlesScene.ts` (Wetter der Region an der Kamera, Wind aus Stärke und Richtung der Wetterperiode wie die Brandausbreitung; Funken/Rauch von Lagerfeuern und Fackeln) und `game/fire.ts` (brennende Kacheln). Einstellungen `particleSettingsFrom` (Wetter/Quellen „reduziert“, Partikellicht Ultra, Blitzreduktion); `__dh.call('particleInfo')` (u. a. CPU-Zeit der Vorbereitung `prepMs`). Szenarien `partikel`, `partikel-20000`, `partikel-gewitter`, `regen`, `schnee`, `ascheregen`, `sandsturm` (`src/debug/partikelScenarios.ts`; die Wetterbilder erzwingen das Wetter der Simulation und suchen eine Periode mit Querwind, `ScenarioRender.particleWind`).
- **Atmosphäre und Post (M5-10, M5-13 … M5-16, M5-22, ADR-0058; `post/`, `passes/{atmosphere,bloom,distortion,post}Pass.ts`):** `installAtmospherePost(passes, upscaler)` (`post/pipeline.ts`, nach der Licht-Pipeline) registriert `corruption` 550 (Paletten-Shift in die Zeile `verderbnis` über eine 32³-Tabelle, Flecken nach `scene.corruption.strength` mit Bayer-Saum, Adern als Isolinien eines Rauschfelds aus zwei inkommensurablen Kacheln in Pixelbreite – dunkler Riss um einen pulsierenden, glühenden Kern, ohne sichtbare Wiederholung (M5-55) –, nur auf flachem Terrain; Wasser bleibt; Bodenpunkt aus Occluder-Maske und -Ring, M5-44), `atmosphere` 700 (Nebeldichte aus drei driftenden Rauschschichten am Boden unter jedem Pixel, dünner mit der Höhe über dem Nebelboden `env.fogFloor`; Nebel in feinen Bayer-Stufen, vom Umgebungslicht beleuchtet, dazu das im Nebel gestreute Licht des Lichtpasses – der Schein endet, wo dessen SDF-Schatten das Licht enden lassen, nie durch Wände, und legt sich wie in der Komposition weich über das Tageslicht (`pointOverDaylight`, M5-41); in Räumen nur ein Hauch, Seitenwände von innen zeigen den Raum, die offene Tür die Außenluft (M5-49); Bodenpunkt jenseits des Flutrahmens aus dem Occluder-Ring (M5-44); Debug-Ansicht `fog`), `distortion` 760 (Versatzfeld RGBA8: Schockwellen und Hitzeflächen aus `scene.post.distortion`, Hitzeflimmern der Ansicht `env.heat`, Unterwasser-Wiegen; Debug-Ansicht `distortion`), `bloom` 780 (Schwelle 1,3 mit weichem Knie, vier Stufen ab halber interner Auflösung, Schein in 32 Bayer-Stufen), `post` 800 (liest das Bild ganzpixelig durch das Feld, Helligkeit nach dessen Divergenz; Tonemapping; Grading über eine 16³-LUT aus Parametern samt Farbenblind-Korrektur; Zustandseffekte, Vignette, Korn, Bayer-Übergang) und `crt` 975 (schaltet nur den Schlussschritt der Präsentation, `Upscaler.finish`). Befüllt von `world/atmosphereScene.ts` (Biome aus 3 × 3 Proben über der Ansicht, Tageslicht und Dämmerung, Wetterüberblendung der Region, Nebelboden aus der Geländehöhe an der Kamera, Zustände des Spielers, Ebenenwechsel) mit den Tabellen `post/atmosphereTable.ts`; Einstellungen `atmospherePostSettingsFrom` (`fog`, `bloom`, `crt`, `colorblind`, Blitz- und Bewegungsreduktion, Screenshake); Debug-Anheftungen `__dh.call('postDebug', name?, wert?)`.
- **Wasser (M5-07 … M5-09, Spiegelung von M5-23, ADR-0059, ADR-0060; `water/`, `passes/waterPass.ts`, Shader `water*`):** `installWater(passes)` (nach der Licht-Pipeline, deren Wasser-Distanzfeld der Pass liest) registriert `water` 600: das HDR-Ziel wird kopiert, Wasserpixel, Eis und die untergetauchten Teile von Figuren werden aus der Kopie neu gezeichnet – alle Versätze, Linien und Funkeln auf ganzen Pixeln. Grund unter dem Wasser um ganze Pixel gebrochen (Neigung der Wellen), Tiefenfärbung aus dem Uferabstand (Wasser-SDF des Occluder-Passes, nach unten begrenzt durch die nächste Landkachel des Kachelrasters – was über dem Wasser gezeichnet ist, eine Krone, eine Figur, ist kein Ufer; ohne SDF eine kurze Suche im G-Buffer), Uferschaum (atmend, zweite gebrochene Linie, Wildwasser unter Wasserfällen, Schaum auf hohen Kämmen), Kaustiken im sonnigen Flachen (feines, gebogenes Netz schwacher Voronoi-Linien, in drei Stufen zur Tiefe ausblendend; M5-62). Spiegelung: Objekte über der Uferlinie per Höhenfeld-Suche die Spalte hinauf (ein Pixel der Höhe h über der Oberfläche spiegelt sich 2h tiefer, nur genaue Treffer – Schwebendes verschmiert nicht), sonst der Himmel aus Palettenfarben nach Tageslicht, Dämmerung (ein tieferes Blau, nie Violett oder Braun – M5-54) und Wolken, nachts Sterne und der Mond mit Phase und Glitzerpfad (bildschirmfest mit leichter Parallaxe), tags Sonnenglitzern als kurze Striche entlang der Wellenkämme auf dem Spiegelpfad der Sonne (Azimut und Höhe), nur wo die Sonne das Wasser erreicht (das Licht der Komposition verrät Baum-, Haus- und Wolkenschatten), unter dem Knie der Bloom-Schwelle; ohne Spiegelung (Niedrig, Mittel) bleibt die schlichte Himmelstönung. Kaustiken, die Züge der kleinen Wellen, die Bewegungsuhr (Kaustik-Wabern, Brandung, Wasserlinie: Präsentationszeit × Bewegungsfaktor, M5-47) und die Funkel-Uhr driften um über die Präsentationszeit integrierte, umbrechende Versätze (`world/drift.ts`, wie Wolken und Nebel; Schlüssel ist der Simulations-Tick – ein Standbild zeigt v · t unter dem letzten Wind, M5-43); der Laufweg eines Zugs bricht erst nach `AMBIENT_WAVES.travelWaves` Wellenlängen um, das Glitzern zählt die Kämme modulo davon (kein gemeinsamer Neuwurf, M5-42). Eintauchmaske: der Schwimmer an der Wasserlinie seiner Schwimm-Frames (Sockel `wasserlinie`), darunter sein Körper als heller, getönter Schatten, der mit der Tiefe verblasst; Watende knöcheltief mit Glanzlinie. Kreaturen im Wasser (M6-Gate, ADR-0168; `CreatureSprites.immerse`) nehmen die Plätze, die der Spieler lässt, die Nächsten zur Bildmitte zuerst: Schwimmer und Amphibien bis `IMMERSION.creatureSwimShare` ihrer Zeichnung unter der Oberfläche, Landtiere im Flachen knöcheltief; ohne eigenen Körper-Frame – das Wasser deckt den Teil unter der Linie, gespiegelt wird nur, was darüber steht. Die Möwe fliegt über dem Wasser und taucht nicht ein. Interaktive Wellen: Wellengleichung (isotroper 9-Punkt-Laplace, gedämpft, Land hält 0) auf einem weltfesten Gitter von 2 px je Texel um die Kamera, zwei RGBA8-Felder im Ping-Pong (16-Bit-Festkomma), 30 Schritte/s auf der Präsentationsuhr; große Flanken als Licht-/Schattenbänder, kleine Ringe als 1-px-Höhenlinien. Impuls-API `scene.water.impulse(art, x, y, faktor)` / `impulseAt` (Figuren, Regentropfen, Pfeile, Fische, Platscher; höchstens 32 je Frame). Winter-Eis: bei Frost wächst Schelfeis vom Ufer (Breite aus der Lufttemperatur, ausgefranster Rand), Platten mit Rissnetz (dunkler Kern, helle Kante), Gletschereis (`eis`-Boden) mit schwächeren Rissen; zugefrorenes Wasser (`WATER_FROZEN`) ebenso. Befüllt von `world/waterScene.ts` (Kachelraster um die Kamera samt Abstand jeder Wasserkachel zur nächsten Landkachel, Himmel aus Kalender und Wetter – neu abgetastet je Schlitz von 15 Kalender-Ticks, bei Uhrsprung, neuer Wetterperiode oder Ebenenwechsel –, Impulse des Spielers, Regentropfen und Fische aus festen Zeitschlitzen). Einstellungen `waterSettingsFrom` (§6.3: Niedrig vereinfacht, Mittel ohne Spiegelung, Hoch/Ultra voll; reduzierte Bewegung für Höhe und Tempo der Wellen, Kaustik-Wabern, Brandung und Wasserlinie; Blitz- und Flackerreduktion für Glitzern, Sternfunkeln, Mondpfad und Gischt). Render-Debugger `wellen`, `__dh.call('waterInfo')` (u. a. CPU-Zeiten `prepMs`). Szenarien `wasser-ufer`, `wasser-spiegelung-tag`, `wasser-spiegelung-nacht`, `wasser-wellen`, `wasser-eis` (`water/scenarios.ts`).
- **Welt-Oberfläche (M5-17 … M5-20, M5-23, M5-24, M5-32, M5-33, ADR-0061 … ADR-0063; `surface/`, `world/surfaceScene.ts`):** `scene.surface` (Wind als Vektor aus Stärke und Richtung der Wetterperiode, Nässe, Pfützenfüllung, Schneedecke – über die Spielminuten integriert, `surface/weathering.ts` –, Laubwechsel der Jahreszeiten über zwei Tage, Figuren, die Gras biegen, Fußspuren im Schnee, Öffnung des Durchblickkreises).
